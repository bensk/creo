# 0005 — Private files: one store, served through the app

**Status:** accepted, October 2026

## Context

Pronunciation recordings are the first files the SIS keeps; photos, PDF slips, and imports follow. PLAN.md planned Cloud Storage with signed URLs.

## Decision

- `core/storage` is the only way to read or write files. It uses the Cloud Storage bucket named by `FILES_BUCKET` (created by Terraform, uniform access, public access prevented, versioned). Without it, development and tests write to `data/files/<env>` (gitignored); production refuses to start a file operation without a bucket.
- Object keys are generated by the app (`pronunciations/<student>/<uuid>.<ext>`), never taken from user input, and checked against a strict pattern.
- Files are served **through the app**, not by signed URL: a route handler checks the session and permission on every request and streams the bytes with `Cache-Control: private`. A file that changes gets a new key and a new row, so responses can be cached as immutable.
- Signed URLs remain an option for large files (PDF batches, imports) where streaming through Cloud Run would be wasteful. Each use needs its own short expiry and a note here.

## Why

Recordings are small (under 512 KB). Going through the app keeps a single permission check and makes revoking access immediate: a signed URL keeps working until it expires, even after someone's session is revoked.
